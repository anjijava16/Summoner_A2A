# AgentVerse Dungeon

A web-based, turn-based RPG where players battle AI bosses using **Google's Agent Development Kit (ADK)** and the **Agent-to-Agent (A2A) protocol**. Players don't pick abilities from a menu — instead, their attacks are dynamically generated by remote A2A agents and validated through class-specific knowledge quizzes, producing a unique narrative every playthrough.

## Concept

AgentVerse Dungeon is a demonstration of multi-agent orchestration applied to an interactive game. The central idea is that each player is represented by a **remote A2A agent** — an external AI service that receives the boss's attack narrative (including a hidden weakness hint) and returns a creative heroic response. The backend then channels that response through a local **Gemini-powered scribe agent** that extracts structured damage data, and the player must answer a tech quiz to confirm the full damage.

### Two Game Modes

| Mode | Players | Boss | Description |
|------|---------|------|-------------|
| **Mini-Boss (Solo)** | 1 | One of 7 thematic mini-bosses | Single player picks a class and fights a randomly selected boss |
| **Ultimate Boss (Party)** | 4 (one of each class) | Mergepocalypse — The Monolith of Managerial Oversight | All four classes cooperate in a strategic 14-turn cycle |

## Architecture

```
┌──────────────────┐       REST API (JSON)       ┌──────────────────────┐
│                  │  ◄─────────────────────────► │                      │
│   React SPA      │                              │  FastAPI Backend     │
│   (Frontend)     │                              │  (Game Logic + AI)   │
│                  │                              │                      │
└──────────────────┘                              └──────────┬───────────┘
                                                             │
                                            ┌────────────────┼────────────────┐
                                            │                │                │
                                            ▼                ▼                ▼
                                   ┌──────────────┐  ┌─────────────┐  ┌────────────┐
                                   │ Remote A2A   │  │ Local LLM   │  │ In-Memory  │
                                   │ Player Agent │  │ Scribe Agent│  │ Game DB    │
                                   │ (External)   │  │ (Gemini)    │  │ (Dict)     │
                                   └──────────────┘  └─────────────┘  └────────────┘
```

- **Frontend** → React 18 SPA served as static files by the backend
- **Backend** → Python FastAPI application handling game logic, state, and agent orchestration
- **Remote A2A Agent** → Player-provided external agent that generates heroic action narratives
- **Local Scribe Agent** → Gemini 2.5 Flash LLM that parses narratives into structured `{damage, message}` JSON
- **Game State** → In-memory dictionary (`game_db`); resets on server restart

### Combat Flow

```
┌─────────────┐     ┌───────────────────┐     ┌─────────────────┐
│  Boss Turn   │────►│  Boss attacks,     │────►│  Player's A2A   │
│  (Auto)      │     │  sends weakness    │     │  agent receives  │
│              │     │  hint to agent     │     │  attack message  │
└─────────────┘     └───────────────────┘     └────────┬────────┘
                                                        │
                                                        ▼
┌─────────────┐     ┌───────────────────┐     ┌─────────────────┐
│  Damage      │◄────│  Scribe Agent      │◄────│  Agent returns   │
│  applied to  │     │  parses narrative   │     │  heroic action   │
│  boss        │     │  → {damage, msg}   │     │  narrative       │
└──────┬──────┘     └───────────────────┘     └─────────────────┘
       │
       ▼
┌─────────────┐     ┌───────────────────┐
│  Quiz shown  │────►│  Correct = full    │
│  to player   │     │  damage applied    │
│  (frontend)  │     │  Wrong = half      │
└─────────────┘     └───────────────────┘
```

1. **Boss attacks** — The backend generates a narrative attack message that includes the boss's weakness as a hint. Damage is dealt to the player(s).
2. **Player agent responds** — The attack message is forwarded to the player's remote A2A agent, which returns an epic heroic action narrative.
3. **Scribe agent parses** — A local Gemini-powered `HeroicScribeAgent` converts the narrative into structured JSON with a damage value and display message.
4. **Quiz validates** — A class-specific quiz is presented. Correct answer = full damage to boss; wrong answer = half damage.
5. **Cycle repeats** — Turns advance through the defined turn order until the boss or all players are defeated.

### Quiz-Based Damage System

Each class has its own quiz bank testing real cloud/AI engineering knowledge:

| Class | Quiz Topics | Questions |
|-------|-------------|-----------|
| **Shadowblade** | Gemini CLI, ADK, MCP servers, design patterns, CI/CD | 17 |
| **Scholar** | RAG systems, BigQuery, vector embeddings, pgvector, Dataflow | 20 |
| **Guardian** | Cloud Build, Cloud Run, vLLM, security, monitoring | 20 |
| **Summoner** | Agent orchestration, SequentialAgent, LoopAgent, A2A protocol | 21 |

### Game Balance

#### Mini-Boss

- **Boss HP:** 600–800 (randomized)
- **Boss Damage:** 110–140 per attack (1/8 chance for half damage)
- **Target fight duration:** ~4–5 rounds

#### Ultimate Boss (Mergepocalypse)

- **Boss HP:** 3,500–6,500
- **Boss AoE Damage per player per hit:**
  - Guardian: 110–170
  - Scholar: 40–80
  - Shadowblade/Summoner: 60–120
- **14-turn cycle:** `Boss → SB → Sch → Sum → SB → Gua → Boss → Gua → Sch → SB → Sum → SB → Sch → SB`

## Backend Deep Dive

### API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/miniboss/start` | Start a solo mini-boss fight. Body: `{a2a_endpoint, player_class, boss_name}` |
| `POST` | `/api/ultimateboss/start` | Start a 4-player party fight. Body: `{a2a_endpoints: {shadowblade, scholar, guardian, summoner}}` |
| `GET` | `/api/game/{game_id}` | Fetch game state. Triggers boss turn processing if `current_turn == "boss"` |
| `POST` | `/api/game/{game_id}/action` | Submit a quiz answer. Body: `{answer_index}`. Returns updated state with damage result |
| `GET` | `/api/config` | Get current game balance configuration |
| `PUT` | `/api/config` | Update game balance configuration |

### Data Models

```python
class GameState:
    game_id: str              # UUID
    game_type: str            # "mini" or "ultimate"
    game_over: bool
    player_won: bool
    current_turn: str         # "boss" or "player_1", "player_2", etc.
    boss: Boss                # {name, hp, max_hp, dialog_phrases}
    players: List[Player]     # [{id, player_class, hp, max_hp, a2a_endpoint}]
    active_quiz: Optional[Quiz]  # {question, answers, correct_index, damage_point, msg}
    turn_order: List[str]     # Ordered turn sequence
    turn_index: int           # Current position in turn_order
    status_message: str       # UI status text
```

### AI Agent Pipeline

The agent system uses a **sequential two-stage pipeline**:

```
Stage 1: RemoteA2aAgent (player_agent)
  ┃  Calls the player's external A2A endpoint
  ┃  Input:  Boss attack message with weakness hint
  ┃  Output: Free-form heroic action narrative
  ▼
Stage 2: LlmAgent (HeroicScribeAgent)
     Model:  gemini-2.5-flash
     Input:  Hero action narrative from Stage 1
     Output: Structured JSON → {damage_point: int, message: str}
```

Both stages run inside an `InMemoryRunner` with async streaming of events. The pipeline is created per-player at game start via `create_heroic_action_agent()` and reused across turns with session management.

**Fallback behavior:** If the remote agent is rate-limited or returns unparseable data, the system falls back to default damage values and a generic action message.

### Quiz Banks

Each class-specific quiz file exports a list of dictionaries with this structure:

```python
{
    "question": "Which serverless compute platform is used to deploy containerized LLM services?",
    "answers": ["Cloud Functions", "Cloud Run", "App Engine", "GKE Autopilot"],
    "correct_index": 1
}
```

A random quiz is selected on each player turn. The agent-generated `damage_point` is associated with the quiz — correct answer applies full damage, incorrect applies half.

### Combat Screen Lifecycle

1. **Mount** — Fetch initial game state, set battlefield background
2. **Boss Turn** — Wait 4s for dramatic pause → poll backend (triggers `process_turn()`) → display boss attack dialog for 8s → cycle boss personality lines every 6s
3. **Player Turn** — Show `QuizModal` → player answers → POST to `/action` → display hero dialog for 3s → show damage numbers
4. **Turn Advance** — Backend cycles `turn_index` through `turn_order` → repeat
5. **Game Over** — Render `GameOverScreen` with win/loss message and return button

### Visual Effects & Animations

- **Character sprites** toggle between idle (`Class.png`) and motion (`Class-motion.png`) states based on turn
- **Turn glow:** Yellow pulsating glow for active player, red glow for active boss
- **HP bars** change color: green (>50%) → yellow (25–50%) → red (<25%)
- **Attack effects** randomly select from 5 hit sprites, displayed for 4s
- **Damage numbers** float up in red, fade out over 16s
- **Dialog bubbles** fade in/out with configurable duration (default 20s)
- **CSS animations:** shake, pulsate-glow, flip-horizontal, rotate-dialog, fadeOut
- **Retro font:** VT323 pixel font throughout the entire UI

## Getting Started

### Prerequisites

- **Node.js** 20+
- **Python** 3.12+
- A running **A2A player agent** with a reachable endpoint (e.g., `http://localhost:8080/player-agent`)
- **Google Cloud credentials** configured (for Gemini API access via Vertex AI)

### Local Development

```bash
# 1. Clone the repository
git clone <repo-url>
cd agentverse-ui-api-dungeon

# 2. Install and build the frontend
cd frontend
npm install
npm run build
cd ..

# 3. Install backend dependencies
cd backend
pip install -r requirements.txt
cd ..

# 4. Set environment variables
export GOOGLE_CLOUD_PROJECT=<your-project-id>
export GOOGLE_GENAI_USE_VERTEXAI=TRUE
export GOOGLE_CLOUD_LOCATION=us-central1

# 5. Start the server
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

The app will be available at `http://localhost:8000`. The backend serves both the API (`/api/...`) and the built frontend static files.

### Deploying to Google Cloud Run

**Using the build script:**

```bash
export REGION=us-central1
export REPO_NAME=agentverse-repo
export PROJECT_ID=<your-project-id>

./run_cloudbuild.sh
```

**Manual build:**

```bash
gcloud builds submit --config cloudbuild.yaml \
  --substitutions=_REGION=us-central1,_REPO_NAME=agentverse-repo,_SERVICE_NAME=agentverse-dungeon,_PROJECT_ID=<your-project-id>
```

The Cloud Build pipeline:
1. Builds a multi-stage Docker image (Node 20 for frontend → Python 3.12 for runtime)
2. Pushes to Artifact Registry
3. Deploys to Cloud Run with 1 min instance, 1 CPU, 2G memory, unauthenticated access
